# Админка

Вкладки: **Обзор** (цифры), **Заявки** (предложенные сайты), **Комментарии** (модерация),
**Сайты** (каталог), **Статьи** (блог), **Пользователи** (Pro, рассылка), **Рассылка** (выбор пяти находок),
**Сервисы** (ссылки на Supabase, Resend, GitHub, Lemon Squeezy и т. д.).

## Вход администратора (заявки, комментарии, пользователи)

Эти вкладки берут данные из Supabase и пускают только аккаунт с `is_admin = true`.
Один раз:
1. Supabase → SQL Editor → выполнить `supabase/002_admin_comments_submissions.sql`.
2. Войти на сайте (`/account/`) своей почтой.
3. Supabase → SQL Editor:
   ```sql
   update public.profiles set is_admin = true where email = 'ваша@почта';
   ```
Дальше админка использует тот же вход, что и сайт (в этом браузере).

## Комментарии — тихая модерация

Писать могут вошедшие пользователи. Новый комментарий автор видит сразу, как опубликованный;
остальные — только после «Одобрить». «Скрыть» — автор не узнает, у него комментарий
останется видимым. Ваши собственные комментарии публикуются без проверки.
Ограничение: 5 комментариев за 10 минут от одного человека.

## Заявки

Форма «Предложить сайт» пишет в таблицу `submissions` (до 4 фото в приватном хранилище,
до 5 заявок в час с одного адреса, скрытое поле против ботов). «Добавить в каталог» открывает
форму сайта уже заполненной; после сохранения заявка отмечается «добавлена».
Telegram, WhatsApp и почта остались запасными способами под кнопкой.

## Каталог (вкладка «Сайты»)

Адрес: **https://atlas.ehroz.pro/admin/** (страница закрыта от поисковиков).

Здесь можно добавить сайт в каталог, изменить его или удалить. Сервер не нужен:
админка сохраняет изменения коммитом прямо в `main` этого репозитория, после чего
GitHub Actions пересобирает и публикует сайт — обычно за 2–4 минуты.

## Первый вход (один раз)

1. Откройте https://github.com/settings/personal-access-tokens/new
2. **Token name** — например, `atlas admin`. **Expiration** — на ваш выбор.
3. **Repository access** → *Only select repositories* → `ehroz1/atlas.ehroz.pro`.
4. **Permissions → Repository permissions → Contents: Read and write**. Больше ничего не нужно.
5. **Generate token**, скопируйте его и вставьте на странице `/admin/`.

Токен хранится только в вашем браузере (галочка «Запомнить»). «Выйти» его стирает.
Если токен утёк — удалите его на GitHub в Settings → Developer settings → Personal access tokens.

## Что умеет

- **Добавить сайт**: адрес, название, категория, цена, платформы, теги, короткое
  описание и описание на русском и английском, альтернативы. ID (адрес страницы
  `/tools/<id>/`) подставляется из названия.
- **Скриншот** можно загрузить свой (обрежется до 16:10, 1440×900). Если не загружать —
  при публикации workflow снимет его сам (`npm run shots`) и закоммитит в
  `src/assets/shots/`. Сайты за защитой от ботов снять не получится — карточка
  покажет домен; тогда загрузите картинку вручную.
- **Изменить** любое поле. Если поменялся текст, дата «изменено» обновится сама.
  Галочка «Переснять скриншот» удалит старый, и при публикации снимется новый.
- **Удалить**: убирает сайт из `tools.json`, из групп в `alternatives.json` и его скриншот.

Каждое действие — отдельный коммит вида `Add … (admin)` / `Update …` / `Remove …`,
так что любое изменение можно откатить через `git revert` или в истории на GitHub.

## Как устроено

- `public/admin/` — статическая страница (`index.html`, `admin.js`, `admin.css`),
  общается только с `api.github.com`.
- Перед каждым сохранением файлы читаются заново из `main`, так что правки, сделанные
  в другом месте, не затираются.
- `.github/workflows/deploy.yml` перед сборкой снимает недостающие скриншоты для сайтов,
  добавленных за последние 14 дней, и коммитит их обратно.
- Категории в админке не редактируются — они в `src/data/categories.json`.

## Статьи (вкладка «Статьи»)

Тот же GitHub-токен, что и для «Сайтов»: войдите на вкладке «Сайты», потом откройте «Статьи».

- **Новая статья**: заголовок, описание (50–160 символов), главный запрос — на русском и
  английском; текст в Markdown. Адрес `/blog/<slug>/` подставляется из заголовка.
- **Сайты из каталога** (минимум 3) встают карточками под статьёй, а у сайтов появляется блок
  «Статьи про …». **Категории** — чипы над заголовком статьи.
- **Обложка**: загрузите картинку — обрежется до 16:9, 1600×900. Без обложки статья покажет
  коллаж из скриншотов выбранных сайтов.
- **Панель над текстом**: заголовки H2/H3 (из H2 собирается «Содержание» сбоку), жирный,
  списки, цитата, таблица, **«Ссылка на сайт»** (на страницу сайта в каталоге),
  **«Скриншот сайта»** (кликабельный скриншот из каталога), **«Картинка…»** (своя картинка,
  загрузится вместе со статьёй), **«Предпросмотр»**.
- **Черновик**: не показывается на сайте. Сохранить статью только на одном языке можно лишь
  черновиком — опубликовать можно, когда есть обе версии.
- **Удалить** убирает папку статьи целиком (тексты, обложку, картинки).

Каждое сохранение — коммит `Add article …` / `Update article …` в `main`; сайт обновится за 2–4 минуты.

## Просмотры статей

Счётчик просмотров хранится в Supabase. Один раз: Supabase → SQL Editor → выполнить
`supabase/003_article_views.sql`. Пока таблицы нет, число просмотров просто не показывается.
Один браузер засчитывается раз в сутки.

## Комментарии к статьям

Работают так же, как у сайтов (та же модерация на вкладке «Комментарии»). В таблице у них
`tool_id` вида `blog-<slug>`, в админке они подписаны «Статья: …».
