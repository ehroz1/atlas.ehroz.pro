# План: нейросеть пишет SEO-статьи для Atlas по трендам

Цель — регулярно (2–3 раза в неделю) выпускать статьи на ru и en, которые
ловят растущие запросы и ведут читателя на карточки каталога
(`/tool/<id>/`, `/category/<id>/`). Нейросеть делает 90% работы, человек —
финальное «да» в pull request.

> Важно: Google и Яндекс наказывают «массовый контент ради выдачи» (Google
> Spam Policies → *scaled content abuse*). Поэтому в плане нет «100 статей в
> день»: каждая статья должна давать то, чего нет у конкурентов, — живой опыт,
> сравнение, свежие факты, скриншоты из каталога.

---

## 0. Что нужно сделать на сайте до запуска (один раз)

Сейчас блога нет. Нужно:

1. **Content collection** `src/content/articles/<slug>/{ru,en}.md` с frontmatter
   (схема ниже) и проверкой через `astro:content` (zod).
2. **Маршруты** `src/pages/[...lang]/blog/index.astro` и `blog/[slug].astro`,
   вид `src/views/Article.astro` по `PAGE-STANDARD.md`.
3. **routes.ts**: новый `PageKind` `'article' | 'blog'` → статьи сами попадут
   в sitemap, `llms.txt`, RSS, OG-обложки.
4. **schema.ts**: `Article` / `BlogPosting` (+ `author` = `AUTHOR.id`,
   `datePublished`, `dateModified`), `FAQPage` — только если в статье есть
   реальный блок вопросов.
5. **Компонент `<ToolMention id="…">`** — карточка инструмента внутри текста
   (берёт данные из `tools.json`, ссылка с `?ref=`). Так нейросеть не может
   выдумать название, цену или URL.
6. **check:seo** расширить: статья не сирота, есть ≥3 внутренние ссылки,
   все `id` в `ToolMention` существуют, ru/en пара на месте.
7. Ссылка «Статьи» в шапке/подвале.

### Frontmatter статьи

```yaml
title: "Лучшие бесплатные нейросети для генерации видео в 2026"   # ≤ 60
description: "…"                                                   # 50–160
slug: free-ai-video-generators-2026
type: listicle            # listicle | comparison | alternatives | howto | news
primaryKeyword: "бесплатные нейросети для видео"
secondaryKeywords: ["нейросеть для видео онлайн", "генерация видео без регистрации"]
tools: [pika, kling, runway]       # только id из tools.json
categories: [ai, video-audio]
published: 2026-11-24
updated: 2026-11-24
trendSource: "Wordstat +240% за 30 дней; GSC: 1.2k показов без клика"
sources: ["https://…", "https://…"]   # куда смотрела нейросеть при фактчеке
reviewedBy: ehroz                     # ставит человек
```

## 1. Конвейер (6 шагов)

```
Тренды → Отбор тем → Бриф → Черновик → Проверка → PR → (человек) → деплой → замер
```

Каждый шаг — отдельный запуск модели со своим промптом и JSON на выходе,
файлы лежат в `content-pipeline/<дата>/`. Так шаги можно перезапускать
по одному и видеть, где ошиблись.

### Шаг 1. Сбор трендов (раз в неделю)

| Источник | Что берём | Зачем |
|---|---|---|
| **Google Search Console** (API) | запросы с показами, но CTR < 2% или позиция 8–30 | самое ценное: спрос уже есть, сайт почти в топе |
| **Яндекс Вебмастер** (API) | то же для Яндекса | ru-аудитория |
| **Яндекс Wordstat** | рост частоты по маскам «нейросеть для…», «бесплатный…», «альтернатива…» | ru-тренды |
| **Google Trends** | rising queries по категориям сайта | en-тренды, сезонность |
| **Product Hunt, Hacker News, GitHub Trending, r/webdev, r/design** | новые инструменты за неделю | темы «новое» и кандидаты в каталог |
| **Ahrefs / Similarweb** (если подключить) | ключи, по которым ранжируются конкуренты, а мы нет | content gap |
| **`tools.json`** | что уже есть в каталоге | статья должна ссылаться на наши карточки |

Выход: `trends.json` — список `{query, lang, source, volume, growth, ourPosition}`.

### Шаг 2. Отбор тем

Модель группирует запросы в кластеры (одна статья = один кластер, чтобы
статьи не конкурировали между собой) и считает балл:

```
score = спрос (0–3) + рост (0–3) + наши инструменты в теме (0–3)
      + слабая выдача / мы на 8–30 позиции (0–2) − уже есть статья (−5)
```

- Берём топ-3 на неделю.
- Отбрасываем темы, где у нас < 3 инструментов в каталоге (нечем подкрепить)
  — их отдаём в список «добавить в каталог».
- Проверяем, нет ли уже статьи по кластеру → тогда задача «обновить», а не «написать».

Выход: `topics.json` с типом статьи, главным и доп. ключами, балл и обоснование.

### Шаг 3. Бриф

Для каждой темы модель:

1. Смотрит топ-10 выдачи по главному ключу (через поиск): какие подтемы
   есть у всех, чего нет ни у кого (это наш шанс), какой средний объём.
2. Определяет интент: «выбрать», «сравнить», «как сделать», «узнать новое».
3. Составляет план H2/H3, список вопросов (People Also Ask → FAQ),
   какие `tools` упомянуть, какие внутренние ссылки поставить.
4. Пишет «уникальный угол» одним предложением — чем статья лучше топа.

Выход: `brief-<slug>.json`.

### Шаг 4. Черновик (ru, затем en)

- Пишется по брифу, сначала ru, потом en — **не дословный перевод**, а
  адаптация (en-ключи свои, примеры свои).
- Факты о инструментах — только через `<ToolMention>` и только из
  `tools.json` + официального сайта инструмента.
- Объём: сколько нужно интенту (обычно 1200–2500 слов), а не «чем больше, тем лучше».

### Шаг 5. Автопроверка (второй проход модели + скрипты)

Модель-редактор (отдельный промпт, «злой редактор») проверяет:

- [ ] Каждое утверждение о цене, лимите, функции подтверждено ссылкой из `sources`
      или помечено `<!-- TODO: проверить -->`.
- [ ] Нет воды: вступление ≤ 3 предложений, первый абзац отвечает на запрос.
- [ ] Главный ключ в title, h1, первом абзаце, одном H2; без переспама.
- [ ] Нет фраз-маркеров ИИ («в современном мире», «давайте разберёмся»,
      «в заключение стоит отметить», «погрузимся»).
- [ ] Тон совпадает с сайтом: коротко, по делу, без восклицаний.

Скрипты: `npm run build && npm run check:seo && npm run check:a11y`.

### Шаг 6. Pull request

GitHub Action открывает PR `articles/<slug>` с обеими версиями, брифом и
отчётом проверки в описании. Человек:

1. Добавляет свой опыт (1–2 абзаца «я пользовался — вот что важно») —
   это главный сигнал E-E-A-T, нейросеть его не подделывает.
2. Проверяет TODO, ставит `reviewedBy`, мерджит.

После деплоя `indexnow.yml` уже отправит новые URL в Яндекс и Bing.

## 2. Обновление старых статей (каждый месяц)

Тренды стареют — старая статья с датой «2026» в январе 2027 теряет клики.

- Скрипт берёт из GSC статьи, у которых за 28 дней упали клики > 30% или
  позиция ушла ниже 10.
- Модель обновляет: новые инструменты из каталога, цены, год в title,
  блок FAQ под новые запросы. `updated` меняется → новый `lastmod` в sitemap.
- Тоже через PR.

## 3. Типы статей, которые подходят каталогу

| Тип | Пример | Ведёт на |
|---|---|---|
| Подборка | «12 бесплатных стоков фото без регистрации» | категория + карточки |
| Сравнение | «Cursor vs Lovable: что выбрать дизайнеру» | 2 карточки |
| Альтернативы | «Бесплатные альтернативы Adobe Firefly» | карточки |
| Как сделать | «Как убрать шум из голоса онлайн» | инструменты задачи |
| Новое | «5 новых инструментов недели для веб-дизайнеров» | новые карточки |

Каждая статья → минимум 3 ссылки на карточки и 1 на категорию;
на карточке инструмента — блок «Упоминается в статьях» (обратные ссылки).

## 4. Системный промпт писателя (основа)

```text
Ты — редактор Atlas (atlas.ehroz.pro), каталога полезных сайтов для дизайнеров,
разработчиков и любознательных. Автор сайта — Ehroz, дизайнер и разработчик из Астаны.

Пиши статью по брифу ниже.

Правила:
1. Первый абзац сразу отвечает на запрос читателя. Без вступлений про «современный мир».
2. Упоминай инструменты только через <ToolMention id="…" /> и только id из списка TOOLS.
   Цены, лимиты и функции бери из TOOLS или из SOURCES. Не уверен — пиши
   <!-- TODO: проверить: … -->, не выдумывай.
3. Для каждого инструмента: для кого он, в чём сильнее соседей, главное ограничение.
   Без маркетинговых прилагательных («мощный», «революционный»).
4. Структура: один h1 (= title без бренда), H2/H3 без скачков, короткие абзацы,
   таблица сравнения, если инструментов больше трёх. FAQ — только реальные вопросы из брифа.
5. Главный ключ: в h1, в первом абзаце, в одном H2. Остальные ключи — естественно, без повторов.
6. Тон: коротко, спокойно, по делу, на «вы» (ru) / plain English (en).
7. Оставь место <!-- AUTHOR: личный опыт --> — его допишет автор.
8. На выходе: frontmatter по схеме + markdown. Ничего кроме файла.

BRIEF: {{brief}}
TOOLS: {{выдержка из tools.json по нужным id}}
SOURCES: {{результаты фактчека}}
```

Отдельно — промпт редактора (шаг 5) и промпт адаптации на en.

## 5. Техническая реализация

- **Модель:** Claude (Opus — бриф и черновик, Sonnet/Haiku — сбор и
  кластеризация трендов, дёшево). Через Claude API или Claude Code в
  GitHub Actions (`anthropics/claude-code-action`).
- **Скрипты** в `scripts/articles/`:
  `collect-trends.mjs` → `pick-topics.mjs` → `brief.mjs` → `draft.mjs` →
  `review.mjs` → `open-pr.mjs`.
- **Workflow** `.github/workflows/articles.yml`: по cron в понедельник,
  плюс ручной запуск `workflow_dispatch` с параметром «тема».
- **Секреты** в GitHub: `ANTHROPIC_API_KEY`, ключ сервисного аккаунта GSC,
  токен Яндекс Вебмастера / Wordstat.
- **Бюджет:** ~3 статьи × 2 языка в неделю — порядка нескольких долларов API.

## 6. Как понять, что работает (смотреть раз в месяц)

- Показы и клики статей в GSC и Вебмастере (статьи → отдельная группа URL).
- Переходы со статей на карточки и `outbound_click` (GA4 / Метрика).
- Доля статей, получивших клики за 60 дней (цель > 50%).
- Если статья 90 дней без показов — переписать под другой ключ или удалить
  с 301 на категорию.

## 7. Порядок запуска

1. **Неделя 1:** блог на сайте (раздел 0), 2 статьи вручную с помощью
   нейросети — отладить шаблон и промпты.
2. **Неделя 2:** скрипты шагов 1–2 (тренды и отбор), запуск руками.
3. **Неделя 3:** шаги 3–6, GitHub Action, первый автоматический PR.
4. **Месяц 2:** обновление старых статей, блок «Упоминается в статьях»,
   первые выводы по GSC.
